# 삭제된 로그 연구

주제

- 별도의 로깅(VPC Flow Logs, S3 Access Logs, Config 등)을 사전에 활성화하지 않아도, AWS 계정 생성 시점부터 **기본적으로(Always-On) 동작하며 절대 끌 수 없는 데이터 소스**
- CloudTrail 로그가 없어지는 상황에서도 AWS 리소스의 상태 변화를 통해 행위를 추정

```

                         │
          ┌──────────────┴──────────────┐
          │                             │
      CloudTrail                    AWS Resources
          │                             │
          │ StopLogging                │
          ▼                             │
     EventBridge                       │
          │                             │
          ▼                             │
       Lambda ◄─────────────────────────┘
          │
          │ Boto3
          ▼
  ┌───────────────────┐

  └─────────┬─────────┘
            │

      State Drift

```

| EC2 |   • InstanceID
  • LaunchTime
  • ImageId
  • VPC Id | 컴퓨팅 자원의 고유 식별자, 부팅 시각, 그리고 백도어 주입 여부를 추적할 수 있는 원본 AMI 기원을 제공합니다. |
| --- | --- | --- |
| S3 |   • Bucket ARN
  • CreationTime
  • Region | 버킷의 명칭과 최초 생성 시각을 통해 데이터 저장소의 기원을 증명하며, 객체 매니페스트를 통해 대규모 삭제·변조 흔적을 포착합니다. |
| IAM |   • UserID
  • RoleId
  • CreateDate | 권한 닻인 `RoleId`와 생성 시각을 고정하여, 공격자가 백도어 권한이나 지속성을 확보하기 위해 몰래 생성한 롤을 100% 잡아냅니다. |
| IAM Access Key |   • AccessKeyId
  • CreateDate
  • UserName | 장기 자격 증명의 고유 ID와 발급 시각을 통해, 시스템 뒤피로 은밀히 발급된 외부 접근 키의 존재를 확증합니다. |
| EBS Volume |   • VolumeId
  • CreateTime
  • SourceVolumeId | 볼륨의 고유 식별자와 생성 시각뿐만 아니라, 스냅샷의 원본 혈통을 통해 랜섬웨어 및 데이터 무단 복제·유출 궤적을 추적합니다. |

### 1. 리소스 상태 자체

- AWS에서 리소스의 현재 존재 여부와 속성값을 의미
- 사용자가 “상태 조회를 끄겠다”고 할 수 있는 스위치가 없음.

한계

- 누가 그 행위를 했는지에 대한 Actor 정보 없음
- 행위 시간은 CreateDate 필드가 있을 때만 추정 가능
- 이미 삭제된 리소스는 흔적이 사라질 수 있다.
